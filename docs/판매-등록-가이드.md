## 새 버전 올리기 (1.0.3에서 실제로 밟은 순서)

빌드된 파일 두 개는 `release` 폴더에 있다. 이름은 버전이 올라가도 그대로이므로 늘 이 두 개를 올리면 된다.

| 파일 | 어디에 |
|---|---|
| `release\Find_Setup.exe` | GitHub 릴리스 (홈페이지 내려받기용) |
| `release\FindInside_Store.appx` | Microsoft Store Partner Center |

### 1) 홈페이지 내려받기 — GitHub 릴리스 (명령으로 할 수 있다)

이 PC에 GitHub CLI(`gh` 2.102)를 깔고 `kimheunghan` 계정으로 로그인해 두었다(토큰은 Windows 자격 증명에 들어 있다). 그래서 릴리스는 명령 한 줄로 끝난다:

```
& "C:\Program Files\GitHub CLI\gh.exe" release create v1.0.3 "D:\Find\release\Find_Setup.exe" ^
  -R kimheunghan/findinside-download --title "FindInside 1.0.3" --notes "바뀐 점"
```

올린 뒤 `gh api repos/kimheunghan/findinside-download/releases/latest --jq .tag_name`으로 `latest`가 새 태그를 가리키는지 확인한다.

브라우저로 할 때는 https://github.com/kimheunghan/findinside-download/releases/new 에서 태그 칸에 `v1.0.3`을 적고 *Create new tag ... on publish*를 누른 뒤, `Find_Setup.exe`를 끌어다 놓고 **Publish release**를 누른다.

이것만 하면 판매 페이지의 "설치 파일(.exe) 직접 받기" 단추가 바로 새 버전을 내려준다. 그 단추 주소가 `releases/latest/download/Find_Setup.exe`라 늘 가장 새 릴리스를 가리키기 때문이다. **Netlify에 다시 올릴 필요가 없다** (페이지 글·그림을 고쳤을 때만 올린다).

### 2) Microsoft Store — Partner Center

1. https://partner.microsoft.com/dashboard 에서 FindInside(Store ID `9MSTC81374SK`)를 연다.
2. **새 제출(Update)** 을 만든다.
3. 패키지 화면에서 이전 패키지를 지우고 `D:\Find\release\FindInside_Store.appx`(161MB)를 올린다.
4. 나머지(설명·스크린샷·연령 등급·외부 결제 선언)는 전과 같으면 그대로 두고 **심사 제출**을 누른다.
5. 심사는 보통 하루 안쪽, 길면 영업일 기준 3일이다. 통과하면 스토어 쪽이 알아서 새 버전으로 바뀐다 ("제품이 인증을 통과하자마자 게시가 시작됩니다").
6. "이 버전의 새로운 기능"은 선택 항목이라 비워도 제출된다. 다만 **"인증 참고 사항(Notes for certification)"** 은 비우면 안 된다 — 심사자에게 체험판 동작과 외부 결제를 설명하는 칸이라 지난 제출 값을 그대로 둔다.

## 남은 일

### 1. 심사 통과 후 실제 판매로 바꾸기

1. Lemon Squeezy 왼쪽 아래 **Test mode** 스위치를 끕니다.
2. 테스트 모드에서 만든 상품을 실제 판매용으로 복사합니다(상품 메뉴의 복사 기능). 라이선스 키 설정(무제한·PC 2대)이 그대로인지 확인합니다.
3. 실제 판매용 상품의 **Share → Checkout Link**와, 번호가 바뀌었다면 Product ID를 알려 주면 `src/product.json`을 바꾸고 설치 파일·판매 페이지를 다시 만듭니다.

### 2. 체험판 내려받기 주소 (완료)

새 버전을 낼 때는 공개 저장소 https://github.com/kimheunghan/findinside-download 에 새 릴리스(예: v1.0.1)를 만들고 `Find_Setup.exe`를 올리면, 판매 페이지 버튼 주소(`releases/latest/download/Find_Setup.exe`)는 그대로 최신 파일을 가리킨다.


설치 파일(약 108MB)을 누구나 받을 수 있는 곳에 올리고 그 주소를 `downloadUrl`에 넣습니다. 소스 저장소(Find)는 비공개로 둘 예정이므로, 설치 파일만 올리는 별도 공개 저장소를 만들어 GitHub Releases에 올리는 방법이 간단합니다. 그러면 주소는 항상 같습니다:
`https://github.com/<계정>/<저장소>/releases/latest/download/Find_Setup.exe`

### 3. 판매 페이지 다시 올리기

값을 채운 뒤 `npm run docs`로 `site/`를 다시 만들고, `site` 폴더(또는 압축 파일)를 Netlify 프로젝트의 **Already built it? → choose a file**로 올립니다.

### 4. 상품 파일

Lemon Squeezy 상품 편집 → **Files**에 `release\Find_Setup.exe`를 올리면 구매자가 구매 확인 메일에서 내려받을 수 있습니다.

### 5. 코드 서명 (권장)

서명이 없으면 처음 실행할 때 Windows가 "PC를 보호했습니다" 경고를 띄웁니다("추가 정보 → 실행"으로 설치 가능). 인증서를 사면 `package.json`의 `build.win`에 설정해 빌드 때 자동 서명합니다. Microsoft Store에 올리면 스토어가 서명해 줍니다(MSIX 필요).

## 판매 전 마지막 확인

- [ ] `npm run dist` 끝에 "판매용이 아닌 시험 빌드" 경고가 없는지
- [ ] 실제 판매 결제 링크로 결제 화면이 열리는지
- [ ] Lemon Squeezy에서 키를 Disable 해 보면 앱이 다음 확인 때 잠기는지
- [ ] 판매 페이지의 구매·내려받기 버튼, 이용약관·개인정보처리방침 링크
- [ ] 이용약관·개인정보처리방침은 일반적인 초안이다. 판매 전에 읽어 보고, 필요하면 전문가 검토를 받는다.

## 라이선스 동작 요약

| 상태 | 화면 | 쓸 수 있는 것 |
|---|---|---|
| 체험 중 (14일) | 위에 "체험판 · N일 남음" | 모든 기능 |
| 체험 끝 | 검색 대신 "체험 기간이 끝났습니다" + 구매·키 입력 | 키 입력만 (색인은 그대로 남음) |
| 정품 | 표시 없음 | 모든 기능 |
| 정품이지만 30일 넘게 인터넷 확인 못 함 | "라이선스를 확인해야 합니다" + 다시 확인 | 확인 후 다시 사용 |
| 환불·중지된 키 | 다음 확인(7일마다) 때 풀림 → 체험 끝 화면 | 키 입력만 |

- 키 확인 때 보내는 것: 라이선스 키, 설치마다 임의로 만든 이름. PC 이름·파일·메일 내용은 보내지 않습니다.
- 다른 가게·다른 상품의 키는 `storeId`·`productId`로 거절합니다.
- 체험·라이선스 상태는 암호화해 두 곳(`%APPDATA%\findinside`, `%LOCALAPPDATA%\FindInside`)에 저장합니다. 시계를 되돌려도 체험 기간이 늘지 않습니다.

## 2026-10-10

- **검색 엔진용 대표 주소를 netlify.app으로** (사용자 결정): pages.dev 페이지 7개의 `<head>`(canonical·og:url·og:image·구조화 데이터)와 `site/sitemap.xml`·`site/robots.txt`를 netlify.app 주소로. 첫 페이지에 canonical 추가. 본문 링크·다운로드 링크는 그대로 각자 주소. 같은 내용이 두 주소로 색인돼 구글이 한쪽을 숨기고 순위 점수가 나뉘던 것을 한 곳에 모음. CLAUDE.md·다음-할-일.md 1-1·PC-MVP.md 설명도 고침

- 구글 검색 결과의 Netlify 로고 원인: 우리 `favicon.ico`가 없으면 **Netlify가 자기 기본 아이콘을 `/favicon.ico`로 내준다** (pages.dev는 없으면 HTML이 나와 구글이 무시하고 우리 아이콘을 씀). 우리 아이콘으로 `web/favicon.ico`(16·32·48px)를 만들고 `build-docs.js`가 `site/`로 복사 — 두 사이트 모두 `/favicon.ico`가 우리 아이콘

- 파일 찾기 페이지 제목을 "파일 검색 프로그램 — 폴더 내 파일 내용 검색"으로, 설명을 "파일 찾기·파일 검색 프로그램 — 폴더 내 파일 내용 검색."으로 시작, 머리말에 "파일 검색 프로그램" (그 말 그대로가 어느 페이지에도 없었다). 첫 페이지 제목은 그대로 — 두 페이지가 검색어를 나눠 맡음

- 구글 검색 결과에 사이트 이름·아이콘이 "Netlify"로 나오던 것 고침: 첫 페이지에 사이트 이름 구조화 데이터(`WebSite`, 이름 "FindInside") 추가, 48·96·192px 아이콘(`web/icon-48/96/192.png`, 256px `icon.png`에서 만듦)을 판매 페이지 7개의 `<link rel="icon">`으로 (구글은 48px 배수 아이콘만 씀). `build-docs.js`가 크기별 아이콘도 `site/`로 복사. 구글 반영은 몇 주 걸림. (같은 날 PDF·엑셀 안내 페이지가 구글에 아직 안 들어간 것을 확인 — 페이지는 정상, 사용자가 색인 요청함)

- "폴더 내 파일 내용 검색", "파일 내용 검색 찾기 프로그램" 검색어 대응: 파일 찾기 페이지 제목을 "폴더 내 파일 내용 검색 프로그램 — 파일 찾기"로, 설명·머리말을 같은 말로, 본문에 "폴더 내 파일 내용 검색"(검색 범위 → 폴더 선택…, 확장자로 좁히기) 단락 추가. 첫 페이지 제목을 "파일 내용 검색·PC 파일 찾기 프로그램 FindInside"로, 설명을 "파일 내용 검색·파일 찾기 프로그램."으로 시작

- 검색 노출 상태를 다음-할-일.md 1에 적음: 네이버는 아직 안 나옴, 구글은 자동 확인 불가, 같은 이름의 다른 프로그램(tkosoft FindInside)이 검색 상위. (처음에 "구글 0건"이라 잘못 적었던 것을 바로잡음 — 0건은 네이버 이야기였다)

- 네이버 사이트 진단 경고 고침: 판매 페이지 5개(첫 페이지·HWP·PDF·엑셀·OCR 안내)의 제목을 40자, 설명을 80자 이내로 줄임. 첫 페이지에 Open Graph 제목·설명·주소·그림 추가 (`web/index.html`; 안내 4개는 `site/`에 직접). robots.txt "없음" 경고는 실제로는 두 사이트 다 200으로 있어 네이버 쪽 재진단만 하면 됨

- pages.dev 첫 페이지에도 네이버 소유 확인 태그(`91e4191f…`)를 넣음 (`web/index.html`). Netlify 복사본은 `scripts/site-netlify.js`가 그 값을 Netlify용(`152b5342…`)으로 바꿔 끼운다 — 사이트마다 자기 태그 하나만

- Microsoft Store 링크를 `https://apps.microsoft.com/detail/9mstc81374sk?hl=ko-KR&gl=KR`로 바꿈 (`src/product.json`의 `storeUrl`). 예전 대문자 주소(`…/detail/9MSTC81374SK`)는 스토어가 두 번 넘긴 뒤(영문 페이지 `hl=en-US`) 열려 느렸다 — 잰 값: 예전 2.1초·넘김 2번, 새 주소 0.9초·넘김 0번. 족보와 같은 원인
- Microsoft Store 링크 2개(위쪽 무료 체험 단추, 설치 안내 글 속 링크)도 새 탭에서 열리게 함 (`STORE_TARGET`). pages.dev·netlify.app 둘 다 적용

- 네이버 서치어드바이저 소유 확인 태그(`naver-site-verification`)를 **Netlify 첫 페이지에만** 넣음 (`scripts/site-netlify.js`가 복사본 `index.html`의 `</head>` 앞에 끼움). 등록 주소가 findinside.netlify.app이라 pages.dev에는 안 넣음

- 판매 페이지 구매 링크 3개를 모두 **새 탭**에서 열리게 함 (`scripts/build-docs.js`의 `newTab`). 족보 사이트와 같게.
- 설치 파일 내려받기 출처를 **사이트별로 따로**: pages.dev에서 받으면 findinside.pages.dev, netlify.app에서 받으면 findinside.netlify.app (`functions/download/[file].js`, `netlify.toml` 프록시 — 다음-할-일.md 2-1)

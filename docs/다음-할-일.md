## 1. Cloudflare Pages로 판매 페이지 옮기기 — **주소 고치기는 끝남, 사이트 만들기만 남음**

Netlify는 크레딧이 떨어져 배포가 멈췄다. 사용자는 Cloudflare 계정(`jocbo.pages.dev` 운영 중)에 여유가 있어 그쪽으로 옮기기로 했다. **새 주소는 `https://findinside.pages.dev`로 정했다**(2026-10-07, 도메인은 사지 않기로 함).

**끝난 것**: 저장소 안 `findinside.netlify.app` 32군데를 `findinside.pages.dev`로 바꿔 커밋했다 (`site/sitemap.xml` 7, 형식별 안내 4개 각 5, `site/robots.txt`, `src/product.json`, README·문서 3). 형식별 안내와 `robots.txt`·`sitemap.xml`은 `npm run docs`가 만드는 파일이 **아니라** `site/`에 직접 든 파일이라 손으로 고쳤다 — 앞으로도 그렇다.

**남은 것 ① Cloudflare Pages 프로젝트 만들기 (사용자가 브라우저에서)**

dash.cloudflare.com → Workers & Pages → Create → Pages → Connect to Git → `kimheunghan/Find` 선택:

| 항목 | 값 |
|---|---|
| 프로젝트 이름 | `findinside` (주소가 `findinside.pages.dev`가 된다) |
| 프로덕션 브랜치 | `main` |
| 빌드 명령 | **비워 둠** |
| 빌드 출력 디렉터리 | `site` |

저장소를 연결해 두면 푸시할 때마다 자동 배포된다. `site/`가 저장소에 그대로 들어 있어 빌드가 필요 없다. 비공개 저장소여도 된다.

**남은 것 ② 구글 서치 콘솔**: 주소가 바뀌면 다른 사이트로 보므로 `findinside.pages.dev` 속성을 새로 추가·확인하고 사이트맵(`https://findinside.pages.dev/sitemap.xml`)을 제출한다. 확인용 `<meta name="google-site-verification">`은 `site/index.html`에 이미 있고 보통 계정 단위라 그대로 통과한다. 새 속성 화면에 다른 태그가 나오면 그걸로 바꾼다. **기존 netlify 속성은 지우지 않는다.**

**남은 것 ③ 저장소 밖 주소** (사용자가 직접): Partner Center 목록의 웹사이트·지원 주소, Lemon Squeezy 가게 설정. `findinside-download` 저장소 README는 `gh`로 대신 고칠 수 있다.

`src/product.json`의 주소는 앱 **정보** 창에 뜨므로 다음 빌드(1.0.4)부터 반영된다.

## 1-1. Netlify 사이트는 따로 둔다 — 리디렉션 안 함, 자기 주소로 저절로 올라감

**결정(2026-10-08)**: 옛 주소 `findinside.netlify.app`을 새 주소로 넘기지 **않는다**. 두 사이트를 서로 연결하지 않고 각각 자기 주소로 따로 둔다. (이전에 적혀 있던 `_redirects` 리디렉션 계획은 사용자가 안 하기로 해서 지웠다.)

저장소의 `site/`는 pages.dev 주소로 되어 있어서 그대로 올리면 Netlify의 sitemap·robots·형식별 안내가 pages.dev를 가리킨다. 그래서 저장소 루트의 `netlify.toml`이 Netlify에게 "`node scripts/site-netlify.js`를 돌린 뒤 `release/site-netlify`를 올려라"라고 알려 준다. 그 스크립트는 `site/`를 복사하면서 주소를 netlify.app으로 바꾼다. Netlify가 저장소를 보고 있으면 푸시할 때마다 저절로 올라간다 (Cloudflare도 같은 푸시로 올라간다).

**끝남(2026-10-09)**: Netlify를 `kimheunghan/Find` 저장소에 연결했고 첫 배포가 17초 만에 Published. 확인 결과 Netlify의 sitemap·robots·형식별 안내가 모두 netlify.app 주소, pages.dev 쪽은 그대로 pages.dev 주소다. 이제 푸시 한 번이면 두 사이트가 각자 주소로 올라간다. (Netlify가 "Pretty URLs" 기능으로 첫 페이지의 `.html` 링크를 `/hwp-search`처럼 바꿔 내보내는데, 정상 동작이고 둘 다 열린다.)

## 2. 스토어 1.0.4 인증 결과 확인

2026-10-08 Partner Center에 `release\FindInside_Store_v1.0.4.appx`를 제출했다 (1.0.3 제출은 취소하고 1.0.4로 바꿈). 인증 중이고, 보통 몇 시간·길면 영업일 기준 3일. 통과하면 자동으로 게시되고, 스토어에서 설치한 사람은 자동으로 1.0.4로 업데이트된다. 거부되면 사유를 보고 고친다.

스토어 앱 1.0.3은 테스트 상품 번호만 알아서 실제로 산 키를 거절한다. 그래서 Lemon Squeezy 상품 설명·대표 이미지에 "1.0.3 이하 버전은 라이선스 키 인식 불가, 1.0.4 이상으로 업데이트 후 입력"을 넣어 두었다. 1.0.3 사용자가 거의 없어지면 대표 이미지를 안내 띠 없는 것으로 되돌린다.

## 3. Lemon Squeezy 테스트 상품 내리기 — 공짜 키 막기

1.0.3 앱의 "구매하기"는 테스트 결제 페이지로 간다. 테스트 결제는 시험용 카드 번호로 돈 없이 통과되고 진짜로 작동하는 키가 나온다 (1.0.4도 테스트 상품 번호 1397740을 받는다).
- **Test mode를 켠 상태에서** Products → 「FindInside 라이선스 (PC 2대)」 → ⋯ → **Unpublish** (Delete 말고). 꺼진 상태에서 하면 실제 판매 상품이 내려간다.
- 족보 테스트 상품은 족보 앱을 Live 결제 링크·상품 번호로 바꾼 새 버전이 나간 뒤에 내린다 (먼저 내리면 족보 앱에서 아무도 못 산다).
- 다음 버전에서는 `productId`에서 테스트 번호(1397740)를 빼는 것도 검토한다.
